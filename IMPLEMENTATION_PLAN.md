# HTTPKit implementation plan

Final dependency decision: BUI-502 revealed incorrect upstream HEAD/204/304
framing. HTTPKit therefore requires the explicit HTTPServer-1.1.0-httpkit.1
compatibility archive generated by compat/build.py from checksum-pinned installed
source, alongside filesystemkit and crypto. The installation and original archive
remain untouched. Unknown source hashes fail closed. Validate raw persistent
HEAD/304/GET and SendFile framing; remove this workaround only after the saved
upstream repro passes against an original newer release. The body suppression
policy below is enforced by that serializer, including direct Response writes.

Build an additive package over the bundled public HTTPServer API. HTTPKitServer
subclasses HTTPServer.OnNotFound and owns its own route table; no builtin routes
are registered. Register routes and middleware before Listen. Handler interfaces
receive a context with the original request/response and explicit captures.

Deliver ordered short-circuit middleware with reverse After callbacks, literal/
parameter/final-wildcard routes, method matching and GET-to-HEAD fallback, SHA256
ETag generation and If-None-Match/304 helpers. Static handler resolves each decoded
path component beneath a configured directory, rejects links/reparse points and
dot/backslash/colon/percent segments, checks size, reads exactly the checked file length within the budget,
serves binary content with no-sniff and no implicit indexes/listings.

Risks: bundled server binds all interfaces and cannot enforce Windows idle
timeouts; static path inspection/open has TOCTOU races and is for trusted immutable
asset trees, not a filesystem sandbox. Whole-file buffering is bounded per request,
not globally. Direct response writes are subject to the required compatibility
serializer's HEAD/bodyless-status framing policy.
Middleware must be thread-safe. Public builtin Get/Any registrations bypass the
router and are explicitly unsupported on this subclass. HTTP caching scope is
If-None-Match GET/HEAD, not If-Modified-Since/If-Range. No TLS changes.

Validation: compile-check authored Buoy sources on six desktop triples; seal a
fresh package and run Linux local HTTP requests checking precedence, case,
methods, middleware stop/order/error unwind, tags, binary static files, traversal,
symlinks, missing/over-limit files, HEAD and conditional requests. Compare ETags
with Python hashlib. Document native versus compile-only platform evidence.
